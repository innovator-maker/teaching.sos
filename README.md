# سند — مجتمع المعلمين المصريين

## مهم جدًا عند الرفع إلى GitHub Pages

لا ترفع `index.html` وحده. الصورة التي تظهر فيها الصفحة كنص عادي تعني غالبًا أن ملفات التنسيق والتفاعل لم تُحمّل. ارفع ملفات الواجهة التالية **كلها في جذر المستودع نفسه** وبالأسماء نفسها:

- `index.html`
- `styles.css`
- `config.js`
- `api.js`
- `app.js`

بعدها افتح رابط الموقع المنشور الذي ينتهي غالبًا بـ `github.io`، وليس صفحة استعراض الملف على `github.com/.../blob/...`. أضف رابط Apps Script في `config.js` قبل تجربة البحث والإرسال. أضفت أيضًا تنسيقًا احتياطيًا داخل `index.html` حتى تبقى الصفحة مقروءة إذا تعذر تحميل ملف CSS الخارجي، لكن التفاعل الكامل لا يعمل دون ملفات JavaScript.

نسخة أولية قابلة للربط والنشر باستخدام GitHub Pages + Google Apps Script + Google Sheets.

## قرار النشر والمراجعة

- كل مشكلة جديدة تُسجل بحالة **قيد المراجعة** ومربع **موافقة النشر** غير محدد.
- كل حل جديد يُسجل مستقلًا وبالحالة نفسها.
- لا يرجع API المشكلة إلا إذا كان مربع الموافقة محددًا **وحالة المراجعة = مقبولة**.
- لا يرجع API الحل إلا إذا كان مربع الموافقة محددًا **وحالة المراجعة = مقبولة**، وكانت المشكلة الأصلية منشورة.
- الاعتماد لا يتم عبر الواجهة العامة. المراجع يحدد مربع الاختيار داخل Google Sheets.
- إلغاء مربع الموافقة يخفي المحتوى فورًا من نتائج API. كما يمكن للمراجع اختيار «مرفوضة» أو «مخفية» من قائمة حالة المراجعة.

> تنبيه: المشروع مهيأ كبداية، ولم يتم نشره في حساب Google أو GitHub الخاص بك. يلزم إكمال خطوات الإعداد أدناه واختبار الخدمة الحقيقية قبل مشاركة الرابط العام.

## محتويات المشروع

```text
index.html                 واجهة عربية RTL
styles.css                 التصميم المتجاوب
app.js                     التفاعل وعرض البحث والمشاركات
api.js                     الاتصال بـ Apps Script عبر JSONP وPOST form
config.js                  رابط API العام الذي ستضيفه بعد النشر
apps-script/Code.gs        البحث والإرسال والتحقق وواجهة API
apps-script/Setup.gs       إنشاء أوراق البيانات والقوائم والـ checkboxes
apps-script/Review.gs      مزامنة Checkbox وحالة المراجعة وسجل القرارات
```

## أولا: إنشاء قاعدة البيانات

1. أنشئ ملف Google Sheets جديدًا، مثل: `سند - قاعدة بيانات المعلمين`.
2. افتح الملف ثم **الإضافات (Extensions) → Apps Script**. بهذه الطريقة يكون المشروع مرتبطًا بالشيت.
3. في محرر Apps Script، أنشئ/استخدم الملفات التالية والصق محتوى الملفات المناظرة من مجلد `apps-script`:
   - `Code.gs`
   - `Setup.gs`
   - `Review.gs`
4. احفظ المشروع، واختر الدالة `setupDatabase` ثم اضغط **Run / تشغيل**. وافق على الأذونات المطلوبة من حسابك.
5. ارجع إلى ملف Sheets وأعد تحميله. ستجد خمس أوراق:
   - `المشكلات`
   - `الحلول`
   - `الإعدادات`
   - `سجل_المراجعة`
   - `البلاغات`
6. افتح ورقة `الإعدادات` وعدّل القوائم كما يناسبك. لا تحذف عناوين الأعمدة في الصف الأول. عمود `نشط` Checkbox، ويمكن إزالة التحديد من أي اختيار لإخفائه عن المعلمين.

**مهم:** لا تجعل ملف Google Sheets عامًا، ولا تشارك صلاحية تحريره مع المعلمين. واجهة المعلمين تتعامل مع API فقط.

## ثانيًا: نشر Apps Script كـ Web App

1. داخل محرر Apps Script اضغط **Deploy → New deployment**.
2. اختر النوع **Web app**.
3. اجعل **Execute as** هو حسابك (مالك المشروع)، حتى يستطيع السكربت الكتابة في الشيت.
4. اجعل **Who has access** هو **Anyone** إذا كان المطلوب استقبال مشاركات من غير تسجيل دخول. قد تمنع بعض حسابات المؤسسات هذا الخيار حسب سياسات المسؤول.
5. اضغط Deploy وانسخ عنوان تطبيق الويب الذي ينتهي بـ `/exec`.
6. إذا عدّلت كود Apps Script لاحقًا، افتح **Deploy → Manage deployments → Edit** ثم اختر إصدارًا جديدًا، وبعدها Deploy. حفظ الكود وحده لا يعني بالضرورة أن إصدار الويب المنشور تحدّث.

رابط Google Apps Script المنشور عنوان عام، لكنه ليس كلمة مرور. لا تضع كلمات مرور أو مفاتيح سرية أو بيانات اعتماد في `config.js`.

## ثالثًا: ربط الواجهة

1. افتح `config.js`.
2. استبدل القيمة:

```js
API_URL: 'PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_EXEC_URL_HERE'
```

برابط `/exec` الذي نسخته، مع إبقاء علامتي الاقتباس.
3. احتفظ ببقية الملفات في المجلد نفسه؛ لا تغيّر أسماء ملفات JavaScript أو CSS المشار إليها في `index.html`.
4. أنشئ مستودع GitHub، وارفع ملفات الواجهة الموجودة في جذر المجلد:
   - `index.html`
   - `styles.css`
   - `config.js`
   - `api.js`
   - `app.js`
   - `README.md` (اختياري لكنه مفيد)
5. افتح **Settings → Pages** في المستودع، واختر النشر من فرع `main` ومجلد `/(root)`، ثم احفظ الإعداد.
6. افتح رابط GitHub Pages بعد اكتمال النشر.

الواجهة تستخدم JSONP للقراءة وللتأكد من حالة الإرسال، وتستخدم HTML form POST مخفيًا للإرسال. هذا المسار يتجنب الاعتماد على `fetch` عابر للنطاقات الذي قد يتعثر بسبب CORS. مع ذلك، يجب اختباره من رابط GitHub Pages الفعلي قبل الإطلاق العام؛ فسياسات الحساب أو النشر قد تختلف.

## رابعًا: اختبار الموافقة — اختبار إلزامي قبل الإطلاق

1. افتح الموقع وأرسل مشكلة تجريبية لا تحتوي على بيانات شخصية.
2. افتح ورقة `المشكلات` وتأكد أنها أُضيفت بحالة `قيد المراجعة` وأن `موافقة النشر` غير محددة.
3. ابحث عن عنوان المشكلة في الموقع. يجب **ألا تظهر**.
4. حدّد Checkbox `موافقة النشر` للمشكلة في الشيت. يجب أن تتحول الحالة تلقائيًا إلى `مقبولة`.
5. ارجع إلى الموقع وابحث مجددًا. يجب أن تظهر المشكلة.
6. أرسل حلًا للمشكلة. تأكد من أن الحل بحالة `قيد المراجعة` وغير ظاهر.
7. اعتمد الحل من ورقة `الحلول` ثم افتح المشكلة مرة أخرى. يجب أن يظهر الحل.
8. ألغِ تحديد Checkbox المشكلة. يجب أن تختفي المشكلة من البحث وتتعذر قراءة تفاصيلها، حتى لو ظلت صفوف حلولها موجودة في الشيت.
9. احذف بيانات الاختبار يدويًا بعد التأكد، أو اتركها مع وسم واضح باعتبارها بيانات اختبار.

## كيف يراجع المسؤول المحتوى؟

- **قبول:** تحديد `موافقة النشر`.
- **سحب النشر:** إلغاء تحديد Checkbox؛ فتعود الحالة إلى `قيد المراجعة`.
- **رفض:** اختيار `مرفوضة` من قائمة `حالة المراجعة`؛ سيزيل السكربت موافقة النشر.
- **إخفاء محتوى منشور:** اختيار `مخفية`؛ سيزيل السكربت موافقة النشر فورًا.
- عمود `ملاحظة إدارية` مخصص للملاحظات الداخلية. لا يُرسل للواجهة العامة.

## احتياطات أمنية وحدود النسخة الأولية

- لا توجد واجهة API لاعتماد المشاركة؛ الاعتماد يدوي من الشيت فقط.
- التحقق من التصنيفات وطول النصوص يتم على الخادم، وليس في المتصفح وحده.
- توجد خانة honeypot وحد مبدئي للإرسال لكل مفتاح متصفح، لكنه **ليس نظام مصادقة قويًا**؛ يمكن تجاوزه بمسح بيانات المتصفح. إذا زاد الاستخدام العام، أضف CAPTCHA أو بوابة API مع حماية أقوى من الإغراق.
- لا تطلب من المعلم بيانات حساسة، واطلب منه عدم إدخال أسماء الطلاب أو بيانات أولياء الأمور. لا تضع في المنصة مشكلات تتضمن معلومات شخصية يمكن التعرف من خلالها على طفل أو معلم.
- النسخة لا تستخدم حسابات مستخدمين، لذلك لا توفر ملكية للمشاركات أو إشعارات لصاحب المشكلة.
- توجد حدود استخدام يومية/متزامنة لخدمات Google. راجع حصص Apps Script قبل التوسع: <https://developers.google.com/apps-script/guides/services/quotas>.
- توثيق تطبيقات الويب: <https://developers.google.com/apps-script/guides/web>.
- توثيق Content Service وJSONP: <https://developers.google.com/apps-script/guides/content>.
- توثيق GitHub Pages: <https://docs.github.com/en/pages>.

## إصلاح الأعطال الشائعة

**لا يمكن الاتصال بالخدمة:** تأكد من استخدام رابط `/exec` وليس رابط محرر Apps Script، وأن الوصول مضبوظ على `Anyone` إن كان متاحًا، وأن آخر نسخة منشورة تحتوي على الكود الحالي.

**تم الإرسال لكن لم تظهر رسالة تأكيد:** افحص Google Sheets قبل تكرار الإرسال لتجنب إنشاء مشاركة مكررة. صفحة الواجهة تذكر ذلك إذا انتهت مهلة التأكيد.

**المشاركة موجودة في الشيت ولا تظهر:** تأكد من أن Checkbox محدد فعلًا، وأن `حالة المراجعة` تساوي `مقبولة`، وأن بيانات الصف موجودة في الورقة الصحيحة.

**الصف الدراسي لا يظهر:** افتح `الإعدادات` وتأكد أن صفوف `الصف الدراسي` مرتبطة بالمرحلة الصحيحة، وأن `نشط` محدد.
